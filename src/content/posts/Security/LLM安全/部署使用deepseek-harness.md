# 前置

根据官方文档

```http
https://github.com/deepseek-ai/deepseek-harness/blob/master/README.zh.md
```

需先安装**Node.js**（要求v16.13或更高版本才可以使用以下命令，低版本直接全局安装），官方下载地址：`https://nodejs.org/zh-cn`。安装完成后，推荐使用Node.js自带的`corepack` 工具来管理`pnpm`（项目依赖包管理器）：

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

也可使用`npm install -g pnpm`全局安装（可能需要管理员权限）。

安装完`node.js`之后，官方给出了两种运行方式，也就是文章接下来，运行部分的内容。

# 运行

## 第一种

直接命令行运行

```shell
npx @deepseek-ai/dsh web
```

## 第二种

从仓库的源码运行

```shell
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```

第二种需要注意：`pnpm run build` 会准备仓库产物。`pnpm dsh web` 会直接使用这些已构建产物，不会重新构建。

一般情况下，如果不对该项目进行添加/修改功能进行二次开发的行为，需要调试源码等等，那么推荐使用第一种即可。

以下是两种运行方式的区别：

|    对比维度     |                **第一种：`npx @deepseek-ai/dsh web`**                |                                 **第二种：`git clone` 源码运行**                                  |
| :---------: | :--------------------------------------------------------------: | :---------------------------------------------------------------------------------------: |
|  **代码来源**   | 从 **npm 官方仓库** 下载的是**预构建好的、压缩过的 JavaScript 产物**（类似于 `.exe` 安装包）。 |               从 **GitHub 仓库** 拉取的是**人类可读的 TypeScript/源代码**（`.ts` 文件、配置文件等）。               |
|  **版本稳定性**  |      默认拉取 npm 上标记为 **`latest`（最新正式版）** 的稳定版本，通常是经过官方测试的发布版。      |       默认拉取 GitHub **`main` 分支的最新代码**，可能包含最新的功能、修复，但也可能**包含尚未发布的 Bug** 或处于开发中的不稳定特性。       |
| **本地磁盘占用**  |         **轻量级**。只会下载运行所需的必要文件到 npm 缓存，不会在你的项目目录里留下大量源码。          | **重量级**。会下载整个仓库（包括 `.git` 历史、测试用例、文档等），并且执行 `pnpm install` 会下载数百 MB 的依赖包（`node_modules`）。 |
| **是否可修改代码** |               **不可以**。你无法修改 npx 加载的代码，它像是一个只读的黑盒。                |            **可以**。你可以随意修改 `deepseek-harness` 文件夹里的任何源码，比如调试、添加日志、修复自己遇到的特定问题。             |

运行成功后，会在本地生成一个 Web 服务（即DSH服务/Web UI），默认访问地址为 `http://127.0.0.1:3080`。首次使用时，需要在Web界面的设置中配置你的**DeepSeek API Key**（可从 DeepSeek 平台获取）。如需添加自定义模型提供方，可参考官方开发文档进行操作。

在这里，如果需要添加自定义提供方，根据开发文档提供的过程操作即可。

# 工作区

DSH的**工作区 (Workspace)**，可以理解为给ai智能体（Agent）划定的一个 **“专属工作地盘”**。

在第一次运行时，会发现Web UI的输入框是灰色的，无法进行使用。因为ai需要一个能实际进行读取、写入和修改文件的具体目录才能开始工作。选定工作区后，ai才能在项目中读写文件、修改代码、运行命令。

工作区也相当于给ai画了一个圈，不让ai接触到其他目录，以防它误操作电脑中的其他重要文件。

除此之外，如果是根据不同项目启动不同的会话，此时工作区还起到了 **“项目管理器”** 的角色。每个工作区都关联着属于自己的多个会话。不同的工作区还可以确保各自不同的项目规则、记忆和上下文关联互不干扰。

## 方案一

## MCP服务器知识点

这里需要了解一些关于方案一中提到MCP服务器的知识：

### 1. 定义

MCP服务器是遵循**MCP 协议**的独立程序，为ai模型提供标准化的外部能力接入。

### 2. 为什么需要它？

ai模型本身是一个“知识渊博但与世隔绝”的大脑，无法直接操作外部系统（文件、数据库、API 等）。MCP协议由**Anthropic公司** 制定并开源，定义了一套标准化的通信规则，让 AI 能够统一、安全地调用各种外部工具。

> 可以把它理解为ai领域的 **“USB-C 接口”**：任何遵循此协议的工具都能即插即用。

### 3. 三大核心功能

|         功能         |               说明                |     类比      |
| :----------------: | :-----------------------------: | :---------: |
|   **工具 (Tools)**   |   可执行的函数，AI 可主动调用（如发送邮件、执行代码）   |   AI 的“手”   |
| **资源 (Resources)** | 只读数据，作为 AI 理解的上下文（如文件内容、API 响应） | AI 的“眼”和“耳” |
| **提示模板 (Prompts)** |      预定义的指令模板，引导 AI 完成特定任务      |   快捷键/模板    |

### 4. 核心架构：三方协作模式

|         角色          |                     说明                     | 餐厅类比  |
| :-----------------: | :----------------------------------------: | :---: |
|  **MCP宿主 (Host)**   | AI 应用本身（如 DeepSeek Harness、Claude Desktop） | 你（顾客） |
| **MCP客户端 (Client)** |             宿主为每个服务器创建的专属通信组件              |  服务员  |
| **MCP服务器 (Server)** |             独立的服务程序，专注提供某一类功能              | 厨房/师傅 |

### 5. 工作流程

1. **连接与能力协商**：启动时，宿主与服务器建立连接，服务器告知其能提供哪些工具/资源。
    
2. **AI 调用**：AI 判断需要某个工具，通过客户端向服务器发起请求。
    
3. **服务器执行**：服务器执行具体操作（如读文件、查数据库）。
    
4. **返回结果**：服务器将结果返回，AI 结合结果生成最终回复。

### 6. 安全特性

- **权限隔离**：每个服务器只接触其工作必需的信息，互不干扰。
    
- **对话历史隔离**：服务器无法看到完整对话历史，只获得当前任务所需信息。
    
- **用户确认**：敏感工具调用通常需要用户手动授权。

### 7. MCP 服务器 vs. Skills

|   对比维度   |    MCP 服务器     |        Skills        |
| :------: | :------------: | :------------------: |
| **解决问题** | “能不能做”——提供具体能力 |    “怎么做”——提供流程编排     |
|  **内容**  |   工具、资源、提示模板   |       指令集、操作流程       |
|  **类比**  | 给 AI 安上“手”和“脚” | 教 AI 如何用“手脚”去“跳舞”的教程 |
|  **关系**  |     基础能力层      |  上层应用层，调用 MCP 提供的能力  |

## 方案二

手动创建

存放路径如下（选择其中一种）：

- `<你的工作区>/.dsh/skills/<技能名称>/SKILL.md`
    
- `<你的工作区>/.agents/skills/<技能名称>/SKILL.md`

**命名规则**：技能名称 (`<技能名称>`) **必须使用kebab-case格式**（例如`my-awesome-skill`）。

**文件格式(如果该skill为自己编写)**：`SKILL.md`文件包含了该技能的具体指令和元数据。

**作用域**：放在工作区下的这些目录，这个 Skill 就**自动属于该工作区**了。

在进行完以上步骤之后，刷新Web界面，无需重启服务，输入`/`就可以看到自行安装的技能。之后就可以按照自己所下载的技能提供的使用方法进行触发。


至此，DeepSeek Harness的安装、运行以及Skills技能的配置与使用已全部完成。你可以根据实际需求，为工作区加载不同的Skills，让ai助手具备更专业、更定制化的能力。
