# V_Jstools

https://github.com/Zjingwen/v-jstools

**浏览器插件拓展，它并不是一款单一的工具，而是集 AST、hook、代码注入、请求修改等等功能于一体的工具箱。**

该插件支持**dom对象hook配置**、注入代码、修改代理/返回值、AST混淆解密、代码模块（RPC）、混淆器等功能，但是常用的还是dom对象hook配置

## 个人理解

**简单来说，这个插件的核心价值在于，它能将逆向分析中最耗时、最关键的“代码定位”环节自动化。**

**在以往**，进行逆向分析（比如分析网站的登录加密）时，流程通常是这样的：

1. **提交请求**：在登录页面输入账号密码并提交。
    
2. **抓包分析**：打开开发者工具（F12），在“网络”（Network）面板中找到包含加密参数的请求。
    
3. **人工猜测与搜索**：根据经验猜测加密可能用到的函数或参数名（如 `encrypt`、`password`、`sign`），然后在“源代码”（Sources）面板中对所有JS文件进行全局搜索，从代码中筛选出可疑的目标。
    
4. **手动验证与调试**：在找到的代码行上手动设置断点，并重新触发登录请求，通过单步调试来最终确认加密逻辑。这个过程非常依赖经验，并且充满试错。

**而使用该插件后**，你只需要提前开启插件的“Hook”功能，然后像正常用户一样提交登录请求。插件会自动在代码的关键执行路径上设置“监控点”。一旦加密函数被调用，插件会立即在控制台输出详细的调用日志，**不仅会显示出被加密的原始数据（比如你输入的密码），更重要的是，它会直接提供一个可点击的链接，**精确指向该被Hook函数在代码中的调用位置（JS文件名和行号）**。

这个位置通常就是**数据处理或请求参数组装的关键代码段**。可以以此为**锚点**，结合上下文分析和调用堆栈，顺藤摸瓜找到最终的加密算法实现、密钥来源等核心逻辑。

# AutoDecode

https://github.com/f0ng/autoDecoder

**Burp插件，根据自定义来达到对数据包的处理（适用于加解密、爆破等），类似mitmproxy，不同点在于经过了burp中转，在自动加解密的基础上，不影响APP、网站加解密正常逻辑等。**

该插件提供三大核心功能：**自带加解密**、**接口加解密**、请求/响应替换和Recipe编辑器。其中，前两个是最常用的

## 配置流程

**配置流程大致如下：**

1. **基础配置**：先在「选项」中指定流量需要经过哪些处理模块，并配置目标域名（可精确到端口），以及用于判断明文/密文的关键字。
    
2. **自带加解密（适用于常规场景）**：
    
    - 在「自带算法加解密」模块中选择对应的加密算法（支持 AES、DES、3DES、RSA、SM2、SM4 等多种常见算法）。
        
    - 根据网站实际情况，填写**模式（如 CBC/ECB）、偏移量、输入密钥、明文、密文**等参数。
        
    - 确认无误后，勾选「添加为请求包加/解密方法」和「添加为响应解密方法」，最后**保存配置**。
        
3. **接口加解密（适用于复杂场景）**：
    
    - 当遇到密钥动态生成、多种加密方式组合、需要计算签名等复杂逻辑时，可以通过自行编写加解密脚本（例如用 Python 的 Flask 框架写一个 Web API 服务），将数据包交由该接口处理。官方也提供了[案例库](https://github.com/f0ng/autoDecoder-usages)供参考。
        

**配置完成后，即可开始抓包测试：**

以登录场景为例，当网站将账号密码等数据加密传输时，可以在burp中捕获到密文请求包。此时，切换到`autoDecoder`扩展选项卡，就能看到解密后的明文内容，此时就可以将该数据包发送到重放器中进行修改重发，或者放到intruder中进行爆破（此时发送出去的数据包为加密状态，与站点相同）等等，该插件方便了进行后续的测试分析。

> **需要说明的是：** 插件名称中的「自动」并非指它能自动识别和破解加密算法。加密算法和密钥通常仍需要你通过逆向分析等手段自行获取。插件的核心价值在于，**将已掌握的加密逻辑自动化地集成到Burp 工作流中**，省去手动加解密的繁琐操作，提升测试效率。

# JSRpc（Rpc:远程调用）

https://github.com/jxhczhl/JsRpc

执行：resouces/JsEnv_Dev.js

区别于传统的扣代码。

## 入门案例

下载两个东西，一个是编译好的`exe`，一个就是项目源码文件。

首先是启动该exe，启动后会生成一个监听端口地址，端口默认为`12080`，也可以在配置文件进行修改

将项目源码`resouces`文件`JsEnv_Dev.js`里面的代码复制粘贴到浏览器的控制台当中

还需要在控制台执行以下代码，目的就是连接监听端口：

```bash
// 此处的ws是websocket协议
// 唯一需要改的就是group处
var demo = new Hlclient("ws://127.0.0.1:12080/ws?group=自定义密钥");
```

以上，就是把当前服务器的控制台权限交给JSRpc控制，JSRpc在此充当一个中间人的效果

当执行完上述操作时，如果成功，cmd的命令行会返回一个上线记录，相当于jsrpc直接与目标站的接口进行通讯（还是和jsrpc的接口通讯，这点留给deepseek回答并解释）？向它发出请求指令，jsrpc就会操控控制台执行这个指令

使用此工具就无需进行详细的逆向过程，只需要知道某个函数是起到加密作用

现在，要在本地创建一个python脚本来连接并控制：

```python
import requests
 
if __name__ == '__main__':
js_code = '''
	console.log("hello");
 '''
url = "http://localhost:12080/execjs"
data = { "group": "自定义密钥", "code": js_code }
res = requests.post(url, data=data)
```

解析：

`console.log("hello");`：向jsrpc发送一个打印hello的指令

`url = "http://localhost:12080/execjs"`：jsrpc的调用接口
